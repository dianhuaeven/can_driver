# can_driver 电机配置变更指南

本文档只讲一件事：当你要在 `can_driver` 里新增、修改、停用或删除电机时，应该改哪些文件、哪些字段必须同步、哪些值会被代码硬校验。

配套参考：

- `config/can_driver.yaml`
- `config/ros_controllers.yaml`
- `launch/can_driver.launch`
- `src/JointConfigParser.cpp`
- `src/CanDriverHW.cpp`

## 1. 先判断你在改哪一类内容

| 变更内容 | 必改文件 | 通常还要改 |
| --- | --- | --- |
| 新增一个电机 / joint | `config/can_driver.yaml` | `config/ros_controllers.yaml`、URDF、上层控制包 |
| 修改 `name` | `config/can_driver.yaml` | `config/ros_controllers.yaml`、URDF、MoveIt、所有引用该 joint 名的脚本 |
| 修改 `motor_id` | `config/can_driver.yaml` | 维护脚本、调试命令、任何写死 `motor_id` 的上层逻辑 |
| 修改 `protocol` / `can_device` / `control_mode` | `config/can_driver.yaml` | `config/ros_controllers.yaml`，必要时同步 launch 启动的控制器 |
| 修改比例尺、方向、ECB IP | `config/can_driver.yaml` | 一般不需要改控制器文件 |
| 停用或删除一个电机 | `config/can_driver.yaml` | `config/ros_controllers.yaml`、`launch/can_driver.launch` 的 `start_controllers`、URDF、上层控制包 |

`can_driver` 的电机映射是以 `can_driver_node.joints` 为中心的。控制器文件只是“谁来控制这些 joint”，不会替代硬件映射。

## 2. 电机配置真正长什么样

`config/can_driver.yaml` 中真正生效的是：

```yaml
can_driver_node:
  joints:
    - name: elbow_pitch_joint
      motor_id: 0x13
      protocol: PP
      can_device: canable1
      control_mode: csp
      position_scale: 65536
      velocity_scale: 65536
      direction_sign: -1.0
```

注意两件事：

1. 所有字段都必须挂在 `can_driver_node:` 下面。
2. `joints` 必须是非空数组；把所有 joint 都删空会直接导致初始化失败。

## 3. 每个 joint 的硬约束

下面这些规则是代码直接校验的，违反后节点会在启动时拒绝通过。

### 3.1 必填字段

每个 joint 都必须有这 5 个字段：

- `name`
- `motor_id`
- `protocol`
- `can_device`
- `control_mode`

缺任何一个，`CanDriverHW::init()` 就会失败。

### 3.2 允许值和取值规则

| 字段 | 规则 |
| --- | --- |
| `name` | 必须是字符串；系统内必须唯一。建议与 URDF joint 名完全一致。 |
| `motor_id` | 支持整数或字符串；字符串可写十进制或十六进制，如 `0x13`。范围必须在 `0..65535`。系统内必须全局唯一。 |
| `protocol` | 只能是 `MT`、`PP`、`DM`、`ECB`。 |
| `can_device` | 必须是字符串，如 `canable0`、`canable1`、`ecb://auto`、`ecb://192.168.10.8`。 |
| `control_mode` | 只能是 `velocity`、`position`、`csp`。 |
| `position_scale` | 必须是正数。若填 `>=2` 的整数，代码会按 PPR 自动换算成 `2*pi/PPR`。 |
| `velocity_scale` | 规则与 `position_scale` 相同，必须是正数。 |
| `direction_sign` | 只能是 `1.0` 或 `-1.0`。 |
| `ip_max_velocity` | 若填写，必须 `>0`。 |
| `ip_max_acceleration` | 若填写，必须 `>0`。 |
| `ip_max_jerk` | 若填写，必须 `>0`。 |
| `ip_goal_tolerance` | 若填写，必须 `>=0`。 |

### 3.3 额外唯一性约束

除了 `joint name` 和 `motor_id` 全局唯一，`can_driver` 还会校验：

- `(can_device, protocol, on-wire node id)` 不能冲突

也就是说，哪怕你写了两个不同的系统层 `motor_id`，如果它们在某个协议下最终落到同一个总线节点号，驱动也会拒绝启动。

### 3.4 协议特定约束

#### `DM`

- 目前只支持 `control_mode: velocity`
- `motor_id` 的低字节必须在 `[0, 15]`
- 若未写 scale，位置和速度默认都按 `1e-4` SI 粒度处理

#### `ECB`

- 可选字段：
  - `ecb_ip`
  - `ecb_discovery`
  - `ecb_refresh_ms`
- `ecb_discovery` 只能写：
  - `true` / `false`
  - `"auto"` / `"fixed"`
- `ecb_refresh_ms` 若填写，必须是正整数
- 当 `protocol: ECB` 且 `ecb_discovery` 不是自动发现时，建议显式给 `ecb_ip`

#### `PP` / `MT`

- 代码层面对 `control_mode` 不做更细的协议限制
- 但现场应按后端实际能力配置：`PP` 常用于 `position/csp`，`MT` 常见于 `velocity`

## 4. 改动时最容易漏掉的同步点

### 4.1 改了 `name`

必须同步检查：

- `config/ros_controllers.yaml`
- URDF 中同名 joint
- MoveIt 控制器映射
- 所有 `/can_driver_node/motor/<joint>/...` 直通调试 topic

`name` 不是注释字段，而是整个 ROS 控制链路的主键。

### 4.2 改了 `control_mode`

必须同步检查控制器文件：

- `velocity` 对应速度接口，通常接 `wheel_controller`
- `position` / `csp` 对应位置接口，通常接 `JointTrajectoryController`

如果你把某个 joint 从 `velocity` 改成 `csp`，但 `ros_controllers.yaml` 里还把它放在 `diff_drive_controller` 下，启动控制器时就会出现接口不匹配。

### 4.3 改了 `motor_id`

必须同步检查：

- `motor_command`、`set_zero`、`apply_limits` 等维护服务的调用脚本
- 手工测试脚本里的 `motor_id`
- 任何按 `motor_id` 做寻址的上层代码

### 4.4 删除一个电机

至少同步四处：

1. `config/can_driver.yaml` 里移除该 joint
2. `config/ros_controllers.yaml` 里把它从控制器关节列表里删掉
3. 如 `launch/can_driver.launch` 的 `start_controllers` 启动集合不再适配，要一起调整
4. URDF / MoveIt / 上层控制包如果还引用这个 joint，也要一起清理

只从 `can_driver.yaml` 删除，而不删控制器里的 joint 名，controller spawner 很可能会报错。

## 5. 推荐变更流程

### 5.1 新增一个电机

1. 在 `config/can_driver.yaml` 的 `can_driver_node.joints` 下复制一个同类 joint 作为模板。
2. 填写 `name / motor_id / protocol / can_device / control_mode`。
3. 根据编码器和协议填写 `position_scale / velocity_scale`。
4. 若实际方向相反，设置 `direction_sign: -1.0`。
5. 若该 joint 要被控制器接管，把它加入 `config/ros_controllers.yaml` 的对应控制器。
6. 若该 joint 会进入整机模型，同步修改 URDF 和上层控制配置。
7. 启动驱动做配置级验证。

### 5.2 修改现有电机

推荐一次只改一类语义：

- 先改映射：`motor_id / can_device / protocol`
- 再改运动语义：`control_mode`
- 最后改换算：`position_scale / velocity_scale / direction_sign`

这样出了问题时更容易定位到底是通信、接口还是标定问题。

### 5.3 停用一个电机

如果是长期停用，推荐直接从配置中删掉或整段注释掉，而不是只让上层“不发命令”。

原因是：

- 只要 joint 还在配置里，它仍然会参与驱动状态、控制器注册和维护接口寻址
- 控制器仍可能尝试声明或接管这个 joint

## 6. 验证步骤

### 6.1 无硬件的最低验证

先做配置解析和控制器声明检查：

```bash
roslaunch can_driver can_driver.launch use_controllers:=false
```

这一步能尽早发现：

- 必填字段缺失
- 协议名 / 控制模式拼错
- 重复 `name`
- 重复 `motor_id`
- 非法 scale / `direction_sign`

如果你还改了控制器映射，再跑：

```bash
roslaunch can_driver can_driver.launch \
  use_controllers:=true \
  start_controllers:="joint_state_controller arm_controller wheel_controller"
```

这一步主要检查 joint 接口和控制器 joint 列表是否匹配。

### 6.2 有硬件时的验证

1. 启动节点。
2. 调用 `~/init`。
3. 观察 `/can_driver_node/lifecycle_state` 和 `/can_driver_node/motor_states`。
4. 必要时用 `~/motor_command` 或直通 topic 单独验证目标轴。

## 7. 一份最小模板

### 7.1 PP 机械臂轴

```yaml
can_driver_node:
  joints:
    - name: elbow_pitch_joint
      motor_id: 0x13
      protocol: PP
      can_device: canable1
      control_mode: csp
      position_scale: 65536
      velocity_scale: 65536
      direction_sign: -1.0
```

### 7.2 DM 底盘轴

```yaml
can_driver_node:
  joints:
    - name: left_front_wheel_joint
      motor_id: 0x01
      protocol: DM
      can_device: canable1
      control_mode: velocity
      direction_sign: 1.0
```

### 7.3 ECB 轴

```yaml
can_driver_node:
  joints:
    - name: ecb_joint_1
      motor_id: 21
      protocol: ECB
      can_device: ecb://auto
      control_mode: position
      ecb_discovery: fixed
      ecb_ip: 192.168.1.20
      ecb_refresh_ms: 10
```

## 8. 最后检查清单

- `can_driver.yaml` 中 `joints` 非空
- 新旧 `joint name` 没有重复
- 新旧 `motor_id` 没有重复
- `protocol` / `control_mode` 拼写正确
- `direction_sign` 只写了 `1.0` 或 `-1.0`
- `DM` 轴仍然是 `velocity`
- 控制器文件中的 joint 列表已经同步
- URDF / MoveIt / 上层包已经同步

如果你只记一条经验规则：`can_driver.yaml` 决定“这台电机是谁、挂哪、怎么换算”；`ros_controllers.yaml` 决定“谁来控制它”。改硬件映射时，先过前者，再看后者。
